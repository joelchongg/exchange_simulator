# Components & Data Flow

## Diagram

![Architecture](../../img/architecture.png)

Dashed boxes are future components while arrows represent data flows.

**Write-ahead input journal:** The sequencer appends every input to the input journal *before* enqueueing it to the Order Queue. This allows the input journal to act as the single source of truth which can be replayable after a crash. Durability level: Page cache.

**Deterministic Engine:** Given the same input journal, the engine produces identical output. All time comes from timestamps stored in the journal. This ensures that replay and recovery is deterministic.

**Output sequence numbers are assigned by the deterministic engine:** Per-channel message seq #s (ITCH/MoldUDP64, each SoupBinTCP session) are assigned by the engine as a function of the input stream, so replay regenerates identical numbers. Receivers dedupe by seq #. This ensures that retransmission and session replay works across restarts.

**One writer for all responses:** Validation, throttling and matching all run on the engine thread. Throttles use the journaled timestamp.

**Two IDs per order:** Client token is private to its session. The engine assigns an exchange reference on accept and the public feed only ever shows the exchange reference. A resting order keeps the exchange reference.

**Ordering is guaranteed within a channel only:** Across channels (e.g. an OUCH fill vs the ITCH execution of the same trade) there is no ordering guarantee. Correlation can be done by match number.

**Every state-changing input goes through the sequencer and journal:** Includes admin/control commands (open, halt, add symbol) and session events.

**Priority:** Price-time priority uses the sequence number generated by the sequencer.

## Components

| Component | Responsibility | Owns | Inputs | Outputs |
|---|---|---|---|---|
| Order Gateway | Terminates SoupBinTCP sessions: login, framing checks (garbage -> disconnect), forwards client inputs, delivers private responses to its session | Per-session state, each owned by its own session thread: session ID, TCP connection, outbound buffer, SoupBinTCP session state | OUCH messages from clients, private responses from the Event Queue, filtered by session ID | Client inputs + session ID -> Sequencer, session events (login, logout, disconnect + reason) -> Sequencer, OUCH responses -> clients |
| Acceptor | Accepts TCP connections and assigns each one to a free session thread. Closes the connection if no session slot is free | Session slot allocation | Listening socket | Accepted connection -> a session thread |
| Admin/Control | User commands: open, halt, resume, close, add symbol | – | User input | Admin commands → Sequencer (journaled like any other input) |
| Sequencer | Puts every input into one total order | Input seq # counter, sequencer timestamp, input journal (append), producer side of the Order Queue | Client inputs (MPSC from gateway threads), admin commands | Journal records -> Input Journal, sequenced inputs -> Order Queue |
| Input Journal | Durable, ordered record of every input | Append-only file of sequenced inputs | Records from the Sequencer | Read by Recovery at startup |
| Matching Engine | Validate -> throttle -> match, one input at a time | Per-symbol order books, order map, per-session throttle state, exchange-reference counter, match # counter, per-channel output seq #s, trading state per symbol | Sequenced inputs from the Order Queue | All responses -> Event Queue |
| Recovery | Engine runs this on startup: replays the input journal before accepting live input | – (runs as the engine) | Input Journal | Rebuilt engine state |
| Output Journal | Derived log of every engine output, in order. Can be regenerated by replaying the input journal | Append-only file of output events | Event Queue | Read by the Retransmission Server |
| Feed Publisher | Packetizes public events into MoldUDP64 and sends them by multicast | Packetization state (current packet, batching) | Public events from the Event Queue | ITCH over MoldUDP64 multicast |
| Retransmission Server | Answers clients' requests for missed feed messages | Request handling state | Retransmission requests from clients, Output Journal | Retransmission responses |

## Data flows

| From -> To | Carries | Transport | Ordering guarantee |
|---|---|---|---|
| Clients → Order Gateway | OUCH messages | SoupBinTCP over TCP, one connection per session | In order per session (TCP) |
| Order Gateway → Sequencer | Client inputs and session events + session ID | MPSC queue (one producer per gateway thread) | Per producer only, the sequencer defines the global order on dequeue |
| Admin/Control → Sequencer | Admin commands | Separate queue | Same as above |
| Sequencer → Input Journal | Sequenced inputs (seq #, timestamp, session ID, payload) | Append to file (page cache) | Seq # order |
| Sequencer → Order Queue → Matching Engine | Sequenced inputs | SPSC queue | Seq # order |
| Input Journal → Recovery → Matching Engine | Sequenced inputs (replay) | File read at startup | Seq # order |
| Matching Engine → Event Queue | All responses (private and public) | Seqlock ring; writer never waits | Engine output order |
| Event Queue → Order Gateway | Private responses for that session | Each gateway thread reads the ring and filters by session ID | Engine output order |
| Event Queue → Feed Publisher | Public events | Seqlock ring read | Engine output order |
| Event Queue → Output Journal | All events | Seqlock ring read | Engine output order |
| Order Gateway → Clients | OUCH responses | SoupBinTCP over TCP | Session seq # order |
| Feed Publisher → Clients | ITCH messages | MoldUDP64 over UDP multicast | Message seq # order; may drop or reorder in transit |
| Output Journal → Retransmission Server | Logged events | File read | Seq # order |
| Clients ↔ Retransmission Server | Requests / retransmitted messages | MoldUDP64 request/response over UDP unicast | Per request |

## Reference trace

Book before: B sells 100 @ 10.00, C sells 100 @ 10.01, D sells 100 @ 10.02. A sends buy 400 @ 10.03.
Expected result: 3 executions, 100 shares of A's order rests at 10.03 under A's exchange reference.

| # | Channel | Message | Key fields |
|---|---|---|---|
| 1 | OUCH → A | Accepted | A's client token, assigned exchange ref |
| 2 | OUCH → A | Executed | 100 @ 10.00, match #1 |
| 3 | OUCH → B | Executed | 100 @ 10.00, match #1 |
| 4 | ITCH | Order Executed | B's exchange ref, 100, match #1 |
| 5 | OUCH → A | Executed | 100 @ 10.01, match #2 |
| 6 | OUCH → C | Executed | 100 @ 10.01, match #2 |
| 7 | ITCH | Order Executed | C's exchange ref, 100, match #2 |
| 8 | OUCH → A | Executed | 100 @ 10.02, match #3 |
| 9 | OUCH → D | Executed | 100 @ 10.02, match #3 |
| 10 | ITCH | Order Executed | D's exchange ref, 100, match #3 |
| 11 | ITCH | Add Order | A's exchange ref, buy 100 @ 10.03 |

- One execution per resting order, never aggregated across price levels.
- Private fills don't reveal the counterparty, the public feed shows exchange refs only.
- The aggressor's remainder appears publicly only once it rests (row 11).
- Rows are listed in engine output order. Across channels, clients may see them in a different order.

## Failure modes

| Failure | Effect | Handling |
|---|---|---|
| Process crash | All in-memory state lost | Restart, with recovery replaying the input journal. |
| Kernel panic or power loss | Journal records still in page cache are lost | Clients may have seen responses for inputs that are no longer in the journal |
| Torn or corrupt journal tail | Replay reads a partial record | Per-record checksum and truncate at first bad record |
| Client sends malformed framing | Cannot parse the stream | Gateway disconnects the session |
| Client disconnects | Session gone, orders still are resting | session events through the sequencer |
| Gateway thread overrun on the Event Queue | Session missed private responses | Disconnect the session, client re-logs in and requests replay. |
| Feed Publisher overrun | Gap on multicast for every client | Treated as fatal; ring sized so it cannot happen |
| Output Journal overrun | Missing events in a derived log | Regenerate by replaying the input journal |
| Retransmission request for a seq # not yet in the Output Journal | Server cannot answer | Ignore/Return RetryAgainLater response or Rejection |
